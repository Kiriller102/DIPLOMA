# Основа структурированного логирования

Пакет не подключён к REST/gRPC и не меняет глобальные логгеры или рабочие цепочки.

- `New(writer, level)` создаёт синхронный JSON-логгер на `log/slog`.
  Writer обязателен; `nil` level означает INFO.
- `NewClassifier(Sentinels{…})` получает доменные ошибки из вызывающего кода.
  `Classify(ctx, err, Options{…})` требует non-nil context и ничего не печатает.
- Для записи ошибки используйте `slog.Any("diagnosis", diagnosis)` и
  `diagnosis.Level()`. Выводятся только класс/тип, SQLSTATE, состояние контекста
  и статические метки; сырой текст ошибок и `pq.Detail` не сериализуются.
  Произвольные атрибуты самого slog-логгера автоматически не очищаются.
- `Annotate(err, operation, stage)` сохраняет `Error()` и `errors.Is/As`.
  Метки — только статические имена, не пользовательские данные; до 64 ASCII
  букв/цифр и `._-`. Некорректные метки заменяются на `unknown`.
  Сводные поля выбирают глубочайшие непустые значения независимо; `contexts`
  сохраняет исходные пары от внутренней аннотации к внешней.
- `errors.Join` сохраняет все листовые причины в `causes`. Итог определяется
  наиболее высоким уровнем, при равенстве — первой причиной. Общая аннотация
  распространяется на все ветви; дедупликации одинаковых ошибок нет.

Основные уровни: успех и ожидаемый отказ — INFO; штатный cancel — DEBUG;
клиентский deadline — INFO, серверный/неизвестный — WARN; внутренний сбой — ERROR.
Успешные health/long-poll timeout — DEBUG; неудачный health — WARN, кроме cancel.
Startup failure — ERROR; shutdown timeout — WARN, самостоятельный сбой — ERROR.

`57014` вместе с `ctx.Err()` или `SourceClient` не доказывает причинную связь:
для обычной операции сохраняется ERROR, состояние контекста записывается отдельно.
Текст PostgreSQL-сообщения не используется для понижения уровня. Источник отмены
задаёт caller; автоматически он не определяется.
